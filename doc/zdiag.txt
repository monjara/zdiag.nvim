1. Introduction					*zdiag-introduction*
							*zdiag.nvim* *zdiag*

zdiag.nvim presents diagnostics from all buffers in one editable buffer.
Each diagnostic is shown with nearby source lines.  Editing those source
lines and writing the zdiag buffer applies the changes to the corresponding
source files.

File headers are display-only.  Diagnostic messages are virtual text and are
not written into source files.  Tree-sitter highlighting is used when a
parser for the source language is available.

Separate source blocks from the same buffer are divided by a display-only
dotted line.  The separator is not written into source files.

==============================================================================
2. Setup						*zdiag-setup*

REQUIREMENTS

zdiag requires Neovim 0.11 or later and diagnostics produced by an LSP client,
linter, or another diagnostic provider.  Tree-sitter parsers are optional and
are used for source highlighting when available.

LAZY.NVIM

Use the |:Zdiag| command as a lazy-loading entry point:
>
  {
    "monjara/zdiag.nvim",
    cmd = "Zdiag",
    keys = {
      {
        "<leader>e",
        "<cmd>Zdiag<cr>",
        desc = "Open diagnostics workspace",
      },
    },
    opts = {},
  }
<

MINI.DEPS

Add zdiag, configure it, and map the same command:
>
  MiniDeps.add({ source = "monjara/zdiag.nvim" })

  require("zdiag").setup()

  vim.keymap.set("n", "<leader>e", "<cmd>Zdiag<cr>", {
    desc = "Open diagnostics workspace",
  })
<

NATIVE PACKAGES

Without a plugin manager, first run `:echo stdpath('data')` to find Neovim's
data directory.  Create its `site/pack/zdiag/start` subdirectory, then clone
zdiag into the native package directory:
>
  git clone https://github.com/monjara/zdiag.nvim \
    "{data-dir}/site/pack/zdiag/start/zdiag.nvim"
<
Restart Neovim, then run `:helptags ALL`.  Neovim loads packages under
`pack/*/start` automatically.  Call |zdiag.setup()| and map |zdiag.open()|
from your configuration if desired:
>
  require("zdiag").setup()

  vim.keymap.set("n", "<leader>e", function()
    require("zdiag").open()
  end, { desc = "Open diagnostics workspace" })
<

The setup call is optional when the default configuration is sufficient.

OPTIONS						*zdiag-options*

The defaults are:
>
  require("zdiag").setup({
    context_lines = 2,
    diagnostics = {
      severity = nil,
    },
    auto_refresh = {
      enabled = true,
      delay = 100,
    },
    jump = {
      mode = "split",
    },
    line_highlight = {
      [vim.diagnostic.severity.ERROR] = "DiagnosticVirtualTextError",
      [vim.diagnostic.severity.WARN]  = "DiagnosticVirtualTextWarn",
      [vim.diagnostic.severity.INFO]  = "DiagnosticVirtualTextInfo",
      [vim.diagnostic.severity.HINT]  = "DiagnosticVirtualTextHint",
    },
  })
<

`context_lines` (`integer`, default `2`)
	Number of source lines displayed before and after each diagnostic.

`diagnostics.severity` (default `nil`)
	Severity filter passed to |vim.diagnostic.get()|.  For example,
	`vim.diagnostic.severity.ERROR` displays errors only, while
	`{ min = vim.diagnostic.severity.WARN }` displays errors and warnings.

`auto_refresh.enabled` (`boolean`, default `true`)
	Rebuild an unmodified workspace after source text or diagnostics change.
	Unsaved changes are never overwritten.

`auto_refresh.delay` (`integer`, default `100`)
	Delay in milliseconds before a scheduled rebuild.  This delay also
	applies to the rebuild scheduled after writing the diagnostics workspace.

`jump.mode` (`"close"`, `"split"`, or `"buffer"`; default `"split"`)
	Controls how |zdiag.jump_to_source()| opens the source buffer:

	  "close"   Close the zdiag buffer and use the current window.
	  "split"   Keep zdiag open and create a split for the source.
	  "buffer"  Keep zdiag loaded and switch the current window to the source.

	Close mode refuses to discard unsaved changes in the zdiag buffer.

zdiag does not define keymaps through its configuration.  See
|zdiag-mappings| for user-defined mapping examples.

DIAGNOSTIC LINE HIGHLIGHTS			*zdiag-line-highlight-config*

`line_highlight` maps diagnostic severities to existing highlight groups.
Only the background-related attributes are copied, allowing Tree-sitter to
continue providing the foreground syntax colors.  The background continues
beneath the virtual diagnostic message to the right edge of the window.

The defaults are:
>
  require("zdiag").setup({
    line_highlight = {
      [vim.diagnostic.severity.ERROR] = "DiagnosticVirtualTextError",
      [vim.diagnostic.severity.WARN]  = "DiagnosticVirtualTextWarn",
      [vim.diagnostic.severity.INFO]  = "DiagnosticVirtualTextInfo",
      [vim.diagnostic.severity.HINT]  = "DiagnosticVirtualTextHint",
    },
  })
<

Use another highlight group name to customize a severity.  Set a severity to
`false` to disable its whole-line background:
>
  require("zdiag").setup({
    line_highlight = {
      [vim.diagnostic.severity.ERROR] = "MyDiagnosticLineError",
      [vim.diagnostic.severity.HINT] = false,
    },
  })
<

3. Using the diagnostics workspace				*zdiag-usage*

OPENING AND CLOSING				*zdiag-opening-and-closing*

Use |zdiag.open()| to open or rebuild the workspace from the current Neovim
diagnostics.
Use |zdiag.close()| to close it.  Closing fails when the workspace has unsaved
changes unless `{ force = true }` is supplied.

The workspace uses the `zdiag` filetype.  File headers such as
"▼ lua/example.lua" are display-only and use |hl-ZdiagHeader|.
Operations invoked from a display-only header, spacer, or separator use the
closest displayed source line.  A separator equally close to both sides uses
the following source block.

EDITING AND WRITING				*zdiag-editing*

Edit the displayed source lines as ordinary buffer text, then use |:write|.
Each changed block is copied back to its source buffer and named source
buffers are written to disk.  File headers and diagnostic messages are not
part of the editable source blocks.

After workspace edits are written, a rebuild is scheduled using
`auto_refresh.delay`.  Source-buffer changes and |DiagnosticChanged| also
schedule a rebuild when `auto_refresh.enabled` is true.  Unsaved workspace
changes are not overwritten by an automatic rebuild.

If a source range changes before an edited workspace is written, zdiag refuses
the write instead of applying stale line positions and potentially overwriting
or duplicating source text.

SOURCE OPERATIONS				*zdiag-source-operations*

Operations such as hover, definitions, rename, code actions, and diagnostic
navigation must run in the source context represented by the current
workspace line.  |zdiag.call()| provides that context for custom mappings.

4. Lua API						*zdiag-api*

All public functions are available from `require("zdiag")`.

							*:Zdiag*
:Zdiag
	Open the diagnostics workspace.  This command can be used as a lazy-loading
	entry point for plugin managers.  It is equivalent to |zdiag.open()|.

setup({opts})						*zdiag.setup()*
	Configure zdiag.  See |zdiag-setup|.  `{opts}` is optional.

open()							*zdiag.open()*
	Open the diagnostics workspace containing diagnostics from all buffers.
	An existing unmodified workspace is rebuilt; an existing workspace with
	unsaved changes is reopened without replacing those changes.

jump_to_source({opts})				*zdiag.jump_to_source()*
	Jump from the current workspace position to its represented source buffer
	using the behavior configured by `jump.mode`.  `{opts}.mode` may be
	`"close"`, `"split"`, or `"buffer"` to override the configured mode for
	one jump.  No value is returned.

close({opts})						*zdiag.close()*
	Close the active diagnostics workspace.  No value is returned.

	Options: ~
	  {force}  (`boolean`, default `false`) Discard unsaved workspace changes.

call({callback})					*zdiag.call()*
	Run `{callback}` in the underlying source context represented by the
	current zdiag cursor or Visual selection.  A Visual selection must stay
	within one source block.  The callback's result is returned.

	Outside the diagnostics workspace, `{callback}` runs normally in the current
	buffer.  This makes one global mapping usable in both contexts:
>
  vim.keymap.set("n", "K", function()
    return require("zdiag").call(vim.lsp.buf.hover)
  end)
<
	Visual-aware callbacks can use the same wrapper in Normal and Visual modes:
>
  vim.keymap.set({ "n", "x" }, "gra", function()
    return require("zdiag").call(vim.lsp.buf.code_action)
  end)
<
	Diagnostic navigation and floats also work through the source context
	provided by `call()`.  Navigation follows the order displayed in the
	workspace and continues across source-buffer boundaries:
>
  vim.keymap.set("n", "]d", function()
    return require("zdiag").call(function()
      vim.diagnostic.jump({ count = 1, float = true })
    end)
  end)

  vim.keymap.set("n", "gl", function()
    return require("zdiag").call(vim.diagnostic.open_float)
  end)
<
	By default, |vim.diagnostic.open_float()| groups all diagnostics on the
	represented source line into one float.  Pass options with a closure when
	different behavior is needed.

5. Mappings						*zdiag-mappings*

zdiag does not define keymaps.  Use a `FileType` autocmd for mappings that
should exist only in the diagnostics workspace:
>
  vim.api.nvim_create_autocmd("FileType", {
    pattern = "zdiag",
    callback = function(event)
      vim.keymap.set("n", "<CR>", function()
        require("zdiag").jump_to_source()
      end, { buffer = event.buf, desc = "Jump to source" })

      vim.keymap.set("n", "q", function()
        require("zdiag").close()
      end, { buffer = event.buf, desc = "Close diagnostics workspace" })
    end,
  })
<

Source operations can instead use one global mapping in both ordinary source
buffers and the diagnostics workspace.  For example:
>
  vim.keymap.set({ "n", "x" }, "gra", function()
    require("zdiag").call(vim.lsp.buf.code_action)
  end)
<

6. Highlight groups					*zdiag-highlights*

							*hl-ZdiagHeader*
ZdiagHeader
	File-header foreground and background.  Defaults to a link to
	|hl-Folded|.  Override it after your colorscheme if desired:
>
  vim.api.nvim_set_hl(0, "ZdiagHeader", {
    bg = "#303540",
    bold = true,
  })
<

							*hl-ZdiagSeparator*
ZdiagSeparator
	Source-block separator foreground.  Defaults to a link to |hl-NonText|.

The following internal groups supply diagnostic-line backgrounds.  Their
attributes are derived from the groups configured by `line_highlight`:

	ZdiagDiagnosticLineError
	ZdiagDiagnosticLineWarn
	ZdiagDiagnosticLineInfo
	ZdiagDiagnosticLineHint
